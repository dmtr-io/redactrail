# Модель угроз

Документ отвечает на вопрос «от чего именно защищает прокси и от чего не защищает».
Он же — граница ответственности: всё, что не описано в разделе «В охвате», считается
незащищённым.

## Активы

1. Персональные данные в контексте: ФИО, телефоны, e-mail, СНИЛС, ИНН, ОГРН, паспорт,
   адреса, даты рождения, номера счетов и карт.
2. Коммерческая тайна: содержимое договоров, суммы, условия, названия контрагентов,
   пометки «коммерческая тайна»/«ДСП».
3. Учётные данные: приватные ключи, API-ключи, токены, пароли в конфигурациях.
4. Метаданные: логин пользователя в путях файлов, имена файлов.

## Противники и поверхности

| Противник | Поверхность | Реакция прокси |
|---|---|---|
| Случайность: агент прочитал файл с ПДн и отправил в контекст | тело запроса | маска ПДн и секретов |
| Секрет в конфиге или в выводе команды | тело запроса | маска (значение уходит провайдеру только как псевдоним) |
| Модель просит закодировать данные (base64, транслит) | текст ответа агента в следующем запросе | эвристики blob/энтропия → маска |
| ПДн спрятаны невидимыми символами или полноширинными глифами | тело запроса | нормализация ввода (zero-width, bidi, NFKC) перед детекцией |
| Картинка или вложение с ПДн | `/v1/files`, блоки `image` | блок по умолчанию; фильтр выключается в админке, тогда вложение уходит без проверки |
| Неизвестный тип контента в запросе | структура payload | блок |
| Пометка «конфиденциально» в тексте | тело запроса | маска; спорные случаи разбирает фоновая модель, ослабления подтверждает человек |
| Ревью находок: хеш цитаты и место в сессии | локальный хост детектора по HTTP | только не-секретные классы; в журнал — классы и хеши, без значений |
| Сеть между прокси и провайдером | TLS | штатный TLS DeepSeek |
| Сеть между DSH и прокси | loopback | не покидает машину |

## Предположения

- Провайдер (`api.deepseek.com`) не доверенный: всё, что ушло, считаем раскрытым навсегда.
- Локальный хост детектора (`127.0.0.1:11434`, `127.0.0.1`) — доверенный по решению
  владельца; трафик до него идёт по HTTP в локальной сети и может быть прочитан в LAN.
- Пользователь не пытается обойти прокси намеренно.
- Ревью блокировок и ночной аудит отправляют локальному хосту детектора маскированный текст,
  а для не-секретных классов — и спорное значение. Это следствие доверия к хосту; секреты
  (`private_key`, `secret_token`, `secret_assign`) не отправляются никогда.
- Блок `thinking` маскируется, а не блокируется: блокировка ломала бы сессию, потому что DSH
  пересылает историю целиком, а подпись блока не переживает изменения текста.
- Содержимое (ПДн, секреты, маркеры, blob) маскируется, а не блокируется: DSH шлёт всю
  историю в каждом запросе, поэтому блокировка содержимого навсегда ломает диалог. Блокируются
  только структура (неизвестные блоки и поля, вложения, превышение размера) и неполные
  номера, которые нельзя замаскировать без риска испортить текст.

## В охвате

- Маскирование персональных данных, реквизитов, секретов, маркеров и blob в `system`,
  `messages`, `tool_result`, `tool_use.input`, `thinking`.
- Блокировка структуры: неизвестных блоков и полей, вложений при включённом фильтре,
  превышения размера, а также неполных номеров.
- Блокировка при неуверенности в структуре (fail-closed), включая недоступность детектора.
- Стабильность псевдонимов: одно значение → один токен во всех запросах.
- Наблюдаемость: журнал классов и хешей, админка с очередью находок, аудит сессий.

## Вне охвата

- **Уже отправленные данные.** Прокси не отзывает и не удаляет то, что ушло до его включения.
- **Косвенная деанонимизация.** Модель может восстановить человека по совокупности признаков,
  не имея прямых идентификаторов.
- **Целенаправленный обход через prompt injection.** Модель может попросить агента разбить
  данные на части, перевести, закодировать или пересказать. Эвристики затрудняют, но не исключают.
- **Утечка через изображения, которые прошли как текст** (OCR-описания, скриншоты в base64).
- **Действия других процессов** на машине пользователя: они видят `~/.dsh` так же, как агент.
- **Приватность хоста детектора**: его журналы, доступ администратора, содержимое памяти.

## Остаточные риски

| Риск | Оценка | Смягчение |
|---|---|---|
| Ложное срабатывание ломает работу | снижена: содержимое маскируется, а не блокируется | режим `audit`, allow-лист, правки из админки |
| Пропуск неизвестного класса ПДн | средняя | регулярное ревью правил, ночной аудит логов |
| Модель-детектор пропускает сущность | средняя | не является единственным шлюзом |
| Выключенный фильтр картинок пропускает вложения без проверки | средняя | галочка в админке видна в настройках; включать обратно для работы с документами |
| Обход через кодирование | низкая-средняя | эвристики, дисциплина агента |
| Компрометация хоста детектора | низкая (LAN, доверенный) | только замаскированный текст, лимит длины |
