# Хранение

Проект хранит только метаданные: классы, хеши, счётчики и конфигурацию.
Значения ПДн и секретов на диск не пишутся.

## Что лежит на диске

| Путь | Содержимое | Ретенция |
|---|---|---|
| `audit/YYYY-MM-DD.jsonl` | запрос: время, байты, классы и счётчики, блокировка | удаляется целиком по дням |
| `audit/blocks-*.jsonl` | блокировки: класс, место, хеш, длина | вместе с днём |
| `audit/suggestions-*.json` | очередь предложений и решений | последние 500 |
| `audit/review-*.json` | отчёты аудита без значений | по дню |
| `state/key.bin` | HMAC-ключ псевдонимов | бессрочно, бэкапить |
| `state/admin-token` | токен админки | бессрочно |
| `state/cache.json` | статистика кеша для админки | перезаписывается |
| `state/backups/` | копии `policy.json` перед правкой | вручную |
| `state/*.log` | события прокси/админки | ротация |

`state/`, `audit/`, `policy.json` не публикуются и перечислены в `.gitignore`.

## Ретенция

`limits.retention_days` (по умолчанию 30). Удаляется файл целиком — это и есть
«забыть»; в базе потребовался бы `VACUUM`.

## Почему JSONL, а не SQLite

- записи только добавляются, читаются последовательно;
- файл за день удаляется одной операцией;
- нет схемы и миграций;
- база не даёт ничего для текущих запросов.

SQLite понадобится, если появится поиск по истории или агрегаты за длинный
период. Тогда JSONL останется журналом истины, SQLite — индексом.

## Объём

Одна строка — сотни байт; при активной работе это единицы мегабайт в день.
Если журнал растёт быстрее, уменьшите `retention_days` или число запросов,
которые пишутся в аудит.
