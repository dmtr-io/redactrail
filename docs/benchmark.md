# Бенчмарк детекторов

Короткая версия: что меряем, сколько получается и как воспроизвести.

## Результат

```
python scripts/bench_detectors.py --corpus tests/corpus/pii_bench.jsonl --gate
```

Корпус: **199 синтетических документов, 421 сущность, ~13,4 тыс. символов**.

| | |
|---|---|
| recall (overlap) | **1.00** |
| precision | **1.00** |
| FP на 1000 символов | **0** |
| latency p95 | **< 2 мс** |

Ключевые классы: `person` 65/65, `user` 33/33, `phone` 34/34,
`address` 32/32, `email` 33/33, `inn`/`ogrn`/`snils`/`passport`/`dob`/`org`
— по 31–33 из 31–33.

`--gate` включён в `scripts/test.ps1`: падение recall/precision ниже порогов
валит прогон.

## Что меряем

- **recall strict** — точные границы;
- **recall overlap** — пересечение: для утечки важнее, закрыто ли значение;
- **recall value** — совпадение после нормализации;
- **precision** — доля верных среди найденных;
- **FP/1k** — ложные срабатывания на 1000 символов;
- **latency p50/p95**.

Strict ниже у `address` и `secret_assign`: правила намеренно захватывают
«адрес:» и `api_key =` целиком. Для защиты от утечки это не проблема, overlap
равен 1.00.

## Корпус

`tests/corpus/pii_bench.jsonl`, генерируется `scripts/make_pii_corpus.py`:
чаты, счета, анкеты, логи, секреты, адреса, негативы (GUID, URL, ISO-дата,
хеш). Значения синтетические, реквизиты — с контрольными суммами.

**Это проверка правил на синтетике, не валидация на реальных данных.**
Реальные имена, адреса и транслит могут пропускаться; для этого есть аудит
и `extra_rules`.

## Ограничения

- корпус собран нами и не покрывает все формы ПДн;
- разметка на уровне значения, а не сущности в предложении;
- цифры 1.00 не означают, что утечек не будет.

## Модель аудита

Отдельный бенчмарк (100 фрагментов, recall/precision/validity/latency) пока не
сделан; текущий файл — только детекторы. ML-эшелон не включён и решается после
этого бенчмарка.
