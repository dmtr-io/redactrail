# Правила, предложенные моделью

Цикл: аудит находит пропуск → модель предлагает регулярку → проверка → человек
принимает или отклоняет. В политику правило попадает только по кнопке.

## Откуда берутся пропуски

Аудит пишет находки `missed_pii` в очередь (`audit/suggestions-<дата>.json`): класс,
файл сессии, номер блока, хеш и длина цитаты. Значения на диске нет — оно
перечитывается по клику, как и раньше.

Кнопка **«Правила по пропускам»** в разделе «Очередь» просит локальную модель
предложить правило по первым пяти пропускам.

## Что видит модель

Не всю сессию, а окно вокруг пропуска (±200 символов). Всё, что правила уже знают,
заменено метками (`<PERSON_1>`, `<PHONE_2>`). Сам пропуск остаётся открытым — иначе
предлагать нечего.

Ответ — строго JSON:

```json
{"pattern": "8[\\s-]?800[\\s-]?\\d{3}[\\s-]?\\d{4}", "flags": "", "explanation": "8-800", "confidence": 0.8}
```

## Проверка до очереди

Предложение отбрасывается, если:

1. шаблон не компилируется или длиннее 300 символов;
2. флаги не из `i`/`m`;
3. есть вложенные квантификаторы — риск зависания;
4. шаблон **не находит** пример, ради которого предложен;
5. шаблон содержит значение **дословно** (кусок из 5+ символов) — правило должно
   обобщать, а не запоминать конкретного клиента;
6. шаблон ловит разрешённое: GUID, URL, ISO-дату, хеш, номер заказа;
7. такое правило уже есть;
8. шаблон медленный на тестовой строке (проверка занимает больше 50 мс).

Прошедшее предложение появляется в очереди как `rule_patch`: паттерн, объяснение,
уверенность модели. Кнопки «Принять» и «Отклонить», как у остальных предложений.

## Применение

Принятое правило попадает в `policy.json` в раздел `extra_rules` при нажатии
**«Применить принятые»** — с бэкапом и записью в журнал:

```json
"extra_rules": [
  {
    "name": "model-user-1a2b3c4d",
    "class": "user",
    "pattern": "[a-z]\\.[a-z]{5,10}",
    "flags": "",
    "explanation": "логин вида a.demenko"
  }
]
```

Правила только **добавляются**: отключить встроенную проверку модель не может.
При загрузке политики шаблон проверяется тем же кодом, что и при старте прокси.

## Ограничения

- Принимать правило стоит после прогона на корпусе: `scripts/bench_detectors.py`.
  Принятие не запускает бенчмарк автоматически.
- Модель может предлагать слишком широкие шаблоны. Проверка ловит явные ошибки,
  но не заменяет чтение человеком.
- Значения не сохраняются: в предложении только паттерн, класс, объяснение и хеш
  примера.
- Нумерация меток и окно контекста зависят от текущей политики; при её смене
  старые пропуски могут перестать открываться — это ожидаемо.
