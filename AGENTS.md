# AGENTS.md

Инструкции для AI-ассистентов и контрибьюторов, работающих с этим репозиторием.
Человеку сначала стоит прочитать `README.md` и `CONTRIBUTING.md`; здесь — только
то, что важно знать перед изменениями кода.

## Что это за проект

Локальный прокси между **DeepSeek Harness** и провайдером: маскирует ПДн,
реквизиты и секреты в исходящих запросах, блокирует неразбираемые структуры,
разворачивает псевдонимы в ответе. Плюс локальная админка и ночной аудит сессий.
Только стандартная библиотека Python, Windows-first, область — только DSH.

- Устройство и гарантии: `README.md`, `docs/threat-model.md`
- Админка и аудит: `docs/admin-ui.md`, `docs/audit.md`
- Правила и хранилище: `docs/rules.md`, `docs/storage.md`
- Как внести вклад: `CONTRIBUTING.md`; уязвимости — `SECURITY.md`

## Быстрые команды

Всё запускается из корня репозитория, `python` — 3.12+.

| Задача | Команда |
|---|---|
| Все тесты | `python -m unittest discover -s tests -t .` |
| Один модуль тестов | `python -m unittest tests.test_scan -v` |
| Гейт бенчмарка (как в CI) | `python scripts/bench_detectors.py --corpus tests/corpus/pii_bench.jsonl --gate` |
| Прокси и админка одним процессом | `python -m redactrail.app` |
| Только админка | `python -m redactrail.admin --root . --port 8788 --no-browser` |
| Только прокси | `python -m redactrail.proxy` |
| Ночной аудит | `python -m redactrail.review --days 1 --limit 50` |
| Проверка утечек | `python -m redactrail.verify` |
| Собрать релизный архив | `python scripts/build_release.py` |
| Проверить установщик из архива | `powershell -ExecutionPolicy Bypass -File .\install.ps1 -SourcePath .\dist\redactrail-0.1.0.zip -NoPython -NoStart` |
| Скан секретов локально | `gitleaks detect --source . --redact -v` (gitleaks 8.30.1) |

Перед коммитом должны проходить тесты, гейт бенчмарка и скан секретов.
CI: `.github/workflows/ci.yml` (Windows-тесты, installer smoke, secret scan);
релиз: `.github/workflows/release.yml` (по тегу `v*`).

## Жёсткие правила

1. **Только стандартная библиотека.** Никаких `pip install` в пути прокси,
   админки и тестов. Внешняя зависимость в горячем пути недопустима.
2. **Windows-first.** Скрипты — PowerShell 5.1-совместимые; пути — Windows;
   Linux/macOS официально не поддерживаются. Не добавляйте допущений, что код
   запустят на Linux.
3. **Вывод в UTF-8.** Любая CLI-точка входа при старте вызывает
   `redactrail.runtime.enable_utf8_output()`: консоль Windows может быть cp1252,
   и кириллица не должна ронять команду. PowerShell-скрипты с кириллицей
   сохраняются в UTF-8 с BOM.
4. **Значения не логируются.** В журналы, ответы API и сообщения об ошибках
   попадают только классы, хеши, длины и смещения. Секреты маскируются и
   **никогда не разворачиваются**; обычные ПДн разворачиваются только в ответе
   провайдера по таблице текущего запроса.
5. **Не коммитить локальное состояние:** `policy.json`, `state/` (ключ
   псевдонимов, кеш, курсор аудита), `audit/`, `tmp/`, `dist/`, `*.log`.
   Публичный пример политики — `policy.example.json`.
6. **Тесты — только `unittest`**, без сети и без реальных ПДн: только
   синтетические данные и `tests.support.scratch_dir()`. Не ослабляйте
   существующие проверки; новые тесты добавляйте рядом с изменением.
7. **Политика по умолчанию консервативна:** неизвестная структура блокируется,
   а не пропускается. Ослабление правил (`allow`, `extra_rules`) — отдельное
   осознанное изменение с тестом.
8. **Секреты и действия в CI фиксируются по версии и хешу.** Например, gitleaks
   скачивается с проверкой SHA256; GitHub Actions — `checkout@v5`,
   `setup-python@v6` (Node 24). Не подключайте непроверенные действия.
9. **`main` — рабочая ветка.** Не переписывайте опубликованную историю и не
   перемещайте теги после публикации. Релизный тег `vX.Y.Z` запускает сборку.
10. **Документация:** русский — основной, английские версии (`README.en.md`,
    `CONTRIBUTING.en.md`) держим в актуальном состоянии; CHANGELOG — Keep a
    Changelog. Ссылки на файлы должны работать.

## Карта кода

```
redactrail/
  proxy.py        HTTP-транспорт, разворот псевдонимов
  sanitizer.py    маскирование/блокировка запроса, склейка находок
  scan.py         координация детекторов
  detections.py   Finding, MASK/BLOCK, применение маски
  entities.py     ФИО, организации, адреса (правила и словари)
  ner.py          локальная NER-модель (опционально)
  ru_names.py     словари имён и отчеств
  checksums.py    контрольные суммы ИНН/СНИЛС/карт
  pseudonym.py    ключ и таблица токенов на запрос
  policy.py       загрузка политики, allow, extra_rules
  audit.py        журнал запросов, блокировки, статистика
  oplog.py        журнал операций для админки
  admin.py        HTTP-админка: очередь, правила, процессы
  review.py       ночной аудит сессий локальной моделью
  recover.py      восстановление значений по хешу (по клику)
  rules.py        просмотр и правка правил
  rule_suggest.py предложения регулярных правил
  verify.py       самопроверка утечек через локальную заглушку
  app.py          единый процесс: прокси + админка
  services.py     планировщик, процессы, health
  runtime.py      настройка консольного вывода
scripts/          установка автозапуска, релиз, корпус, бенчмарк, демо
tests/            unit-тесты и синтетический корпус (pii_bench.jsonl)
docs/             threat model, аудит, админка, правила, хранилище
install.ps1       установщик; uninstall.ps1 — удаление
policy.example.json  публичный пример политики
```

## Определение готовности (definition of done)

- `python -m unittest discover -s tests -t .` — зелёный;
- гейт бенчмарка — зелёный;
- gitleaks — без находок (ложные срабатывания помечены `gitleaks:allow` или
  `.gitleaksignore`, с комментарием, почему это синтетика);
- затронутые документы и `CHANGELOG.md` обновлены;
- в diff нет секретов, локальных путей и имён пользователя;
- для изменений установщика — прогон `install.ps1`/`uninstall.ps1` из архива;
- CI зелёный, включая `Secret scan` и `Installer smoke test`.

## Чего не делать

- не добавлять сторонние зависимости и не превращать проект в «фреймворк»;
- не логировать и не возвращать в API исходные значения;
- не коммитить `policy.json`, `state/`, `audit/`, `tmp/`, `dist/`;
- не менять `policy.example.json` под свою локальную машину;
- не ослаблять проверки и не удалять тесты ради зелёного CI;
- не пушить публичную историю в архивный remote (`internal`);
- не делать force-push в `main` и не переписывать историю после публикации.
